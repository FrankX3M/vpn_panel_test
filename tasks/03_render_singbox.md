# ТЗ 03 — Render sing-box config

**Контракт:** `contracts/03_render_singbox.md`
**Зависимости:** `01_db_models` (типы `User`/`ServerConfig` как вход)
**Файлы:** `src/core/render/singbox.py`, `tests/core/render/test_singbox.py`

## Задача

Реализовать `render_singbox_config(users, server) -> dict` строго по контракту. **Перед реализацией
свериться с актуальной документацией sing-box** (схема JSON меняется между версиями) — контракт
даёт ориентир по форме, но не гарантирует 100% актуальность полей на момент выполнения задачи.

## Критерии приёмки

- [ ] На вход: 2 активных юзера (один только с `.vless`, второй с `.vless` и `.hysteria2`),
      1 неактивный юзер (`is_active=False`) с `.vless` — неактивный НЕ должен попасть в результат.
- [ ] Результат — валидный JSON (сериализуется через `json.dumps` без ошибок).
- [ ] Reality-inbound содержит `short_id` для каждого активного юзера с `.vless`.
- [ ] VLESS `users[]` содержит `uuid` каждого активного юзера с `.vless`, и не содержит неактивных.
- [ ] Hysteria2-inbound аналогично фильтрует по активности и наличию `.hysteria2`.
- [ ] Пустой список `users` → функция не падает, возвращает валидную структуру с пустыми списками
      пользователей внутри inbound'ов.
- [ ] Отсутствие обязательных полей в `server` (например, `reality_dest == ""`) → `ValueError`
      с понятным текстом, не голый `KeyError`/`AttributeError`.
- [ ] `ruff`/`mypy`/`pytest` проходят. Функция не открывает файлы, не импортирует `core.svc`.

## Отдельная сессия для тестов

Эта функция — кандидат №1 на правило "тесты пишет другая сессия/модель" из пайплайн-гайда: легко
подсунуть заведомо кривой `ServerConfig` (пустые поля, юзеры без аккаунтов) и проверить, что
поведение на границе соответствует контракту, а не тому, что "само получилось" при первой реализации.
